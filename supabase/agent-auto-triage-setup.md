# AI Agent auto-triage setup

1. Run `supabase/migrations/20260828120000_agent_foundation.sql` first (Phase 1 — chat agent, provider keys, `agent_actions` approval queue) if not already applied.
2. Deploy `agent-auto-triage`. Set `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (or `SUPABASE_SECRET_KEY`/`SUPABASE_SECRET_KEYS`), and a new secret `AGENT_TRIAGE_SECRET` (any long random string — this is the shared secret the database uses to authenticate to the function, since a Database Webhook has no logged-in user) as Edge Function secrets.
3. Wire the trigger. Try the Dashboard first: Database → Webhooks → Create a new hook (table `communications`, event `Insert` only, target the `agent-auto-triage` function, header `X-Agent-Triage-Secret: <same value as AGENT_TRIAGE_SECRET>`). If that fails with `schema "supabase_functions" does not exist` (seen on this project — the dashboard feature isn't fully provisioned), run `supabase/migrations/20260830130000_agent_auto_triage_trigger.sql` by hand in the SQL Editor instead, after filling in the real secret in place of `<AGENT_TRIAGE_SECRET>` — it creates the same effect directly via `pg_net.http_post`, which was already installed on this project. Never commit that file with the real secret filled in.
4. In Settings → AI Agent (in the app), an admin must configure at least the Claude key — auto-triage skips the model step (still creates the contact/task) if no provider key is configured for the organization.
5. Verify with a real test message: send an email or WhatsApp message from an address/number not already in Contacts. Confirm: a new contact appears, a task appears assigned to the matter's responsible lawyer (or the connected mailbox/WhatsApp admin if no matter), and — only if the message content warrants it — a calendar entry and/or a card in AI Agent → Pending approval. Confirm nothing is ever sent without an operator clicking Approve there.

Contact matching for existing senders reuses the same logic email-sync and the WhatsApp webhook already use (`match_whatsapp_phone`, the Gmail contact-matching in `supabase/migrations/20260826120000_email_contact_matching.sql`) — this function only fills the gap where no existing contact/client matched.
